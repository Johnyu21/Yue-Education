## 数据库接入方式与边界

使用原 PostgreSQL 配置，没有另起一套正式数据库连接。
只准备新增 m5_daily、m5_report、m5_chat；引用正式 sys_user、sys_department ID。
原因：原 employee_daily_report 的状态约束只有 DRAFT/SUBMITTED，而已讨论方案需要审核通过、退回、已通过内容快照；用户已允许新增表，但不改组员字段。

原 employee_daily_report 保持原样，其历史数据不会自动出现在 M5 新日报表中。
目前没有发现其他已实现模块写入原日报表。后续若 M3 开始写原日报表，需要先协调唯一数据来源，不能各写一张表后直接混算。
原日报路径在新增入口中读写 m5_daily；日报 ID 是 UUID 字符串，与原表数字 ID 不能混用。
数据库迁移脚本只新增本模块表，不执行 ALTER、DROP、全库 create_all 或实验数据导入。

报告按需生成，先由 Python 计算指标，Dify 负责整理文字；日报汇总使用审核通过的快照。
心理/投诉来源事件与日报关联去重；未关联补充单列，不伪称为新增业务事件。
客户“签约”使用 signed_at，不冒充实际入学；意向是当前状态，不能还原历史意向。
现有心理模块需要 psych_access_enabled；班主任身份由 sys_class.head_teacher_id 识别，主管由本部门 head_user_id 识别，不新增或更改组员角色枚举。
