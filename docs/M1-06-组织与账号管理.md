## 二、设计说明

### 2.1 为什么部门要防"树循环"

**问题**：部门是树形结构（`parent_id` 指向上级）。
如果不检查，可能出现：
```
A 的上级是 B
B 的上级是 A        ← 成环！
```
**遍历部门树时会死循环**，服务直接卡死。

**所以**：改上级时往上追溯，**发现目标是自己或自己的后代 → 拒绝**。

### 2.2 为什么"班主任必须是员工"

**问题**：如果学生能当班主任，会出现**学生看全班同学的数据** ——
严重的隐私越权。

**所以**：指定班主任时校验 `user_type='EMPLOYEE'`。

### 2.3 为什么"主管"用部门关系而非 role

**问题**：如果用 `employee_role='主管'` 存身份，会出现**两个真相源**
（部门表的 `head_user_id` 和用户的 `role` 可能不一致）。

**所以**：主管 = `sys_department.head_user_id` 是我。**唯一事实源**。

**注意**：改 `employee_role` 不需要处理主管 —— 主管身份**不在 role 里**。

### 2.4 为什么"停用员工"要先检查

**问题**：直接停用一个班主任，他带的班**没人管了** ——
学生请假没人批、心理预警没人跟。

**所以**：停用前检查：
- 是否还是班主任 → 要求先交接班级
- 是否还带在读学生 → 要求先交接学生

### 2.5 为什么改权限要 `token_version+1`

**问题**：一个人被降权（如撤销售后能力），但他**手上的旧令牌还有效** ——
他还能继续访问。

**所以**：改敏感权限时 `token_version+1` → **旧令牌立即失效**。

## 四、使用方式

### 4.1 建部门

```python
from app.services import organization_service as svc

with with_business_transaction(db):
    dept = svc.create_department(db, code="TECH", name="双元制事业部", parent_id=None)
    # ⚠️ parent_id 传自己的后代 → 抛 InvalidRequestError
```

### 4.2 建班级（⚠️ 班主任自动校验）

```python
with with_business_transaction(db):
    cls = svc.create_class(
        db, code="CLS_A", name="2026春季A班",
        dept_id=dept_id, head_teacher_id=teacher_id)
    # ⚠️ 传学生 id → 抛"班主任必须是员工"
```

### 4.3 指定主管（唯一事实源）

```python
with with_business_transaction(db):
    svc.update_department(db, dept_id, head_user_id=user_id)
    # 写 sys_department.head_user_id，不是改 role
```

### 4.4 建员工账号

```python
with with_business_transaction(db):
    user, plain_pwd = svc.create_employee(
        db, username="zhangsan", real_name="张三",
        employee_role="ADVISOR", dept_id=1)
    # ⚠️ plain_pwd 只在这一次返回，数据库只存哈希
```

### 4.5 停用前检查

```python
svc.check_can_deactivate(db, user_id)
# 若还是班主任 / 还带在读学生 → 抛 StateConflictError
```

## 五、注意事项

| ❌ 不要 | 为什么 | ✅ 应该 |
|---|---|---|
| 直接改 `role` 来表示"主管" | 两个真相源会打架 | 改 `head_user_id` |
| 跳过 `_assert_valid_teacher` | 学生当上班主任 → 越权 | 用 `create_class`/`update_class` |
| 直接停用带学生的顾问 | 学生没人管 | 先 `check_can_deactivate` |
| 改权限不升 `token_version` | 旧令牌还能用 | `update_user` 已自动处理 |
| 主管给自己加权限 | 越权 | 已被拦（测试覆盖） |
| 建账号时明文存密码 | 泄露 | 用 `create_employee`（内部哈希） |
