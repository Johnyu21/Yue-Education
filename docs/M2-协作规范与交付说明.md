## 五、统一接口规范（沿用 M1/M4 现状）

1. **响应结构**：`{code, message, data, request_id}`；成功 `code="OK"`。
2. **命名**：请求体 `snake_case`，**响应字段 `camelCase`**（与 M1 的 `auth.py`、M4 全部接口一致）。
3. **分页**：`{items, page, pageSize, total}`，`page` 从 1 起，`pageSize` 默认 20、最大 100；列表用稳定排序 `(create_time, id)` 防漏项。
4. **ID / 时间 / 金额**：ID 一律十进制字符串；时间 ISO 8601 带时区；纯日期 `YYYY-MM-DD`；金额字符串 + 币种。
5. **越权**：不在范围内一律返回 **404**（不是 403），防探测数据存在性；无岗位能力才返回 403。
6. **写入 DTO 白名单**：全部 `extra="forbid"`；`owner_user_id` / `dept_id` / `status` / `profile_summary` / `assessment_report` / `latest_score` 等**永不接受客户端传入**。
7. **幂等/并发**：新建与业务事件用 `request_key`（唯一键）；改已有记录用 `expected_version` 条件更新。

### 5.1 M2 涉及的错误码

| HTTP | code | 场景 |
|---|---|---|
| 422 | `VALIDATION_ERROR` | 通用字段校验 |
| 422 | `MISSING_FIELD` | 表单渠道缺性别/城市/学历；访客报名缺姓名/手机号 |
| 422 | `PERIOD_INVALID` | 活动 `end_at<=start_at` 或 `signup_deadline>start_at` |
| 422 | `NO_READABLE_TEXT` | 简历/PDF 无可提取文本（扫描件） |
| 409 | `DUPLICATE_CODE` / `DUPLICATE_REGISTRATION` | 项目编码重复 / 同活动同手机号重复报名 |
| 409 | `RULE_NOT_APPROVED` / `CAPACITY_BELOW_REGISTERED` | 无规则不能审核 / 名额低于已报名数 |
| 409 | `REGISTRATION_CLOSED` / `REGISTRATION_NOT_CANCELLABLE` | 活动未开放或已截止 / 已签到等不可取消 |
| 409 | `ASSESSMENT_RUNNING` | 该客户已有研判进行中 |
| 409 | `EVENT_FULL` / `VERSION_CONFLICT` | 名额满 / 乐观锁冲突（`data.current_version`） |
| 429 | `RATE_LIMITED` | 公开接口超频 |
| 502 / 503 / 504 | `AI_BAD_RESPONSE` / `AI_UNAVAILABLE` / `AI_TIMEOUT` | Dify 异常 |

> ⚠️ 上表中 `MISSING_FIELD`、`PERIOD_INVALID`、`NO_READABLE_TEXT`、`DUPLICATE_CODE`、`RULE_NOT_APPROVED`、`CAPACITY_BELOW_REGISTERED`、`REGISTRATION_CLOSED`、`DUPLICATE_REGISTRATION`、`REGISTRATION_NOT_CANCELLABLE`、`ASSESSMENT_RUNNING` 出自 `04_API接口文档` 的逐接口约定，定义在 `app/services/m2_errors.py`；`docs/M1-01-公共契约冻结.md` 的错误码表**尚未收录**，待 P1 收编进 `core/errors.py`。

## 六、权限与敏感数据

| 数据 | 要求 | M2 的实现 |
|---|---|---|
| 客户主档 | 本人负责 / 主管本部门 / 管理员全域 | `build_scope(db, user, "lead")` + `get_or_404`（越权 404） |
| 未路由客户（`dept_id` 为空） | 仅管理员可见（待分配池） | 主管范围按 `dept_id` 过滤，自然排除 |
| 匿名留资回执 | 不得泄露客户是否存在 | 新客户与老客户回执**结构完全一致**，只有 `{accepted, receiptNo}` |
| 公开项目/活动 | 不展示未发布项目、草稿活动、员工手机号、未审规则 | 公开 DTO 与员工 DTO 分离；未发布 → 404 |
| 活动名额 | 页面数字不可信 | `SELECT ... FOR UPDATE` 锁活动行后在锁内复查，叠加 `UNIQUE(event_id, mobile)` |
| 访客取消凭据 | 不明文存储 | 确定性 HMAC，明文只随首次成功响应返回，库中仅存 sha256 |
| 简历附件 | 归属校验 | 只接受 `u/{actor_id}/` 前缀且文件存在的 `object_key`，越权 404 |
| 日志 | 不入敏感信息 | 手机号 `mask_mobile` 脱敏；取消凭据与临时密码不落日志 |

## 七、Dify 契约

- 统一约定：Start 变量 `payload_json`（JSON 字符串），End 变量 `output_json`（JSON 字符串），后端解析一次并按 `mode` 校验；AI 调用一律在**事务之外**。
- 两个工作流的节点均为：`开始 → 解析入参(code) → [知识检索] → LLM → 输出净化(code) → 结束`。
  **代码节点不可删**：解析节点负责拆变量（让知识检索只用访客消息做 query），净化节点负责剥
  ` ``` `/解释文字、强制合法 JSON、意图与字段白名单、丢弃 `score/decision`、缺项归一。
- `WF_VISITOR`（`dify/wf_entry.yml`，key `DIFY_VISITOR_KEY`）：公开问答 / 留资草稿 / 活动意向 / 越界拒绝；**不得泄露客户资料**，不得声称"已提交"，不承诺名额。
  入参含 `draft`（已收集草稿）与 `history`（最近 8 条问答），用于多轮续填与指代消解。
- `WF_ASSESSMENT`（`dify/wf_profile.yml`，key `DIFY_ASSESSMENT_KEY`）：只做字段提取 + 证据定位 + 缺项，**不输出分数与录取结论**（判定与打分由 Python 按已审核 `admission_rules` 计算）。
  入参含 `required_fields`，`missing_fields` 只能取自该清单。
  **学历 `education` 是唯一无条件必填项**；语言成绩、出生日期、城市等属附加项，
  只有项目规则引用到时才必填（规则引用了就进缺项并导致 `NEEDS_INFO`）。
- `DIFY_MODE`：`mock`（离线样本，确定性、不编造）/ `live`（真实调用）/ `disabled`（直接降级）。
  工作流调用失败或输出不合契约时，访客客服返回 `aiStatus="UNAVAILABLE"` 降级回答，不影响表单与查询；
  `aiStatus` 统一由 `integrations.dify.ai_status()` 产出。
- 详细变量说明见 `dify/variables.md`；评测样本见 `dify/eval_samples.md`。
