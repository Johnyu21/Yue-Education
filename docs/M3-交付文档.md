## 3. 已确认业务规则

| 项 | 规则 |
|---|---|
| 转派通知 | 新 owner + 原 owner 都通知 |
| 转学生通知 | 个人顾问 + 本部门主管；正文绝不含临时密码 |
| 管理员建客户 | 可指定 dept；owner 恒为本人 |
| 认领 | 条件更新 owner IS NULL + version，并发只有一人成功 |
| SIGNED | 只能由转化入口设置；状态接口拒绝 |
| 流失 | 必须写原因；恢复需说明 |
| 主管代办 | 本部门主管可审批/转派本部门单 |
| 心理 NOTE | M4 口径（跟进人 + 本人顾问 + 班主任） |
| 到期跟进 | 不做状态过滤，设过计划且到期即算 |
| 调班/换顾问 | 有未审单必须先转派，否则 409 |
| 日报 | M5 负责，助手只做草稿提议 |
| 成绩 | 只查不写（D02） |
| NL2SQL | 方案 A+：意图 + 预审模板 + 白名单聚合指标 |
| 写入执行 | 后端执行 + 提议确认，Dify 不直连写接口 |
| 助手回答 | 只返回文本；会话上下文 15 分钟 |

## 10. M5 前端集成要点

1. **响应格式**：`{code,message,data,request_id}`；响应字段 camelCase；ID 一律字符串；分页 `{items,page,pageSize,total}`。
2. **越权**：404（不是 403）；无岗位能力才 403（如 `CAPABILITY_DENIED`）。
3. **写操作**：统一带 `request_key`（UUID）与 `expected_version`；冲突返回 409 且 `data.current_version` 可展示。
4. **助手提议**：`data.proposal` 含 `operation/entityId/preview/expectedVersion/requestKey/confirmationToken/expiresAt`；前端展示完整预览，用户确认后调对应普通接口并原样回传 `request_key` + `confirmation_token`；5 分钟过期需重新生成。
5. **待办路由**：`actionRoute` 示例 `/employees/leads/{id}`、`/services/{id}`、`/employees/feedback-tickets/{id}`、`/employees/psych-alerts/{id}`；打开后仍需后端鉴权。
6. **敏感数据**：学生/员工 DTO 不含密码、投诉正文、心理原文；前端不要依赖隐藏按钮做权限。
7. **转学生响应**：`initial_credentials` 仅首次出现，前端需强提示“线下交接、一次性”，不要写入 localStorage 或日志。
