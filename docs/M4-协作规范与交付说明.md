> M3 的审批/售后/预警处置/转派等控制器，**不要直接拼 SQL 写我的表**，调用下面这些函数即可（事务边界在 M3 控制器）。

| 对应 M3 接口 | 业务函数 | 所在模块 |
|---|---|---|
| API054 审批 | `student_service.decide_service(db, actor, service_id, req)` | `app/services/student_service.py` |
| API055 转派 | `student_service.assign_service(db, actor, service_id, *, assignee_user_id, expected_version, reason, request_key)` | 同上 |
| API061 售后认领 | `feedback_service.claim_feedback(db, actor, ticket_id, *, expected_version, request_key)` | `app/services/feedback_service.py` |
| API062 售后处理 | `feedback_service.handle_feedback(db, actor, ticket_id, req)` | 同上 |
| API072 预警处置 | `psych_service.review_alert(db, actor, alert_id, req)` | `app/services/psych_service.py` |

### 调用示例（M3 照抄即可）

```python
from app.core.transaction import with_business_transaction
from app.schemas.service import ServiceDecisionRequest
from app.services.student_service import decide_service

@router.post("/api/v1/services/{service_id}/decision")
def decide(service_id: int, data: ServiceDecisionRequest, user=Depends(require_password_changed), db=Depends(get_db)):
    with with_business_transaction(db):
        dto = decide_service(db, user, service_id, data)   # user 即当前登录员工
    return ok(dto.model_dump(mode="json"))
```

> 每个函数内部已做：状态机校验、乐观锁 `version`、权限/范围校验、处理历史追加、通知（同事务）。M3 只需把请求体解析成对应 Schema 传入。

## 五、统一接口规范（M5 前端必读）

1. **命名**：请求字段 snake_case（`service_type`），响应字段 camelCase（`studentProfileId`、`assigneeDisplayName`）。
2. **ID**：一律字符串（`"1001"`），前端不要用 `number` 存。
3. **时间/日期**：时间 ISO 8601 带时区（`2026-10-18T12:46:34Z`），纯日期 `YYYY-MM-DD`。
4. **分页**：返回 `{items, page, pageSize, total}`，`page` 从 1 起，`pageSize` 默认 20 最大 100。
5. **枚举**：后端全英文，前端用 `frontend/src/types/enums.ts` 翻译成中文。
6. **错误码**：`403` 无岗位能力、`404` 不存在或越权、`409` 版本/状态冲突、`422` 校验、`502/503/504` AI。
7. **越权返回 404 而非 403**（防探测数据存在性），前端统一按"资源不存在"处理。

### 助手写操作的两步确认流程（M5 重点）

```
学生发消息 → 助手返回 proposal（含 preview + requestKey + confirmationToken + expiresAt，5 分钟）
  → 前端展示完整卡片 → 用户点确认 → 调普通接口（原样回传 preview 字段 + requestKey + confirmationToken）
  → 后端校验后落单 → 返回真实编号
```

> ⚠️ 助手文本里的"已提交"不是业务回执；以普通接口返回为准。前端不要跳过确认直接写库。

### 敏感字段隔离（前端不可依赖"隐藏按钮"）

- 学生端工单响应**没有 `priority`**；助手响应**不含情绪/风险字段**。
- 投诉正文、心理观测、处理历史只对有权限的员工返回。

## 七、Dify 契约（后端/运维）

- 学生助手工作流 `WF_STUDENT`：`POST {DIFY_BASE_URL}/v1/workflows/run`。
- 输入 `inputs.payload_json`（JSON 字符串），输出 `data.outputs.output_json`（JSON 字符串，后端解析校验）。
- 配置：`.env` 里 `DIFY_BASE_URL` + `DIFY_STUDENT_KEY`（**key 只放 .env，不进 git/Dify 提示词**）。
- 未配 key 时，API030 返回 `ai_status=UNAVAILABLE` 降级回答，**不影响其它接口**。
- 详细契约见 `dify/variables.md`，工作流导入说明见 `dify/wf_student.yml` 顶部注释。
