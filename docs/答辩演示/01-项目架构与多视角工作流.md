# 粤教留学服务平台 · 项目架构与多视角工作流

> 生成日期：2026-10-19
> 适用场景：答辩讲解、项目交接、新人上手
> 一句话定位：**面向粤教服务的智能教育服务平台——访客获客 → 客户研判 → 学生服务 → 智能报告。**

---

## 一、项目一句话与核心价值

平台把留学服务从「散落在微信、Excel、纸面」的流程，收拢为一条可追踪、可审核、可审计的数字化链路：

```
访客浏览项目
   → AI 客服答疑 / 留资 / 活动报名
   → 客户线索进入公共池
   → 顾问认领、跟进、研判
   → 签约转学生
   → 学生服务（档案、成绩、日程、申请、请假、反馈、心理）
   → 日报沉淀
   → 6 类智能报告与 Word/PDF 导出
```

三个核心设计原则：

1. **AI 只建议、不落库**：AI 输出草稿或提议，必须由本人点击确认，才走普通业务接口写库。
2. **权限在 SQL 层收敛**：数据范围直接变成 `WHERE` 条件，越权一律 404，不暴露数据是否存在。
3. **AI 可降级**：Dify 不可用时，业务表单、日报、报告指标仍然可用，不阻断办理。

## 二、技术架构

### 2.1 技术栈

| 层 | 技术 |
|---|---|
| 前端 | Vue 3 + TypeScript + Vite，hash 路由，单页应用 |
| 后端 | Python 3.12 + FastAPI + SQLAlchemy 2 + Pydantic |
| 数据库 | PostgreSQL（云端 `yue_education`，独立业务库） |
| AI | Dify 工作流（访客、研判、企业助手、学生助手、报告生成、报告助手） |
| 部署 | Windows 一键脚本 / Docker Compose / 云端 |
| 测试 | 后端 pytest + 前端 Vitest + 浏览器流程检查 |

### 2.2 后端分层

```
HTTP 请求
   ↓
controllers/      薄路由：解析入参、取身份、调 service、统一返回
   ↓
services/         业务核心：状态机、事务、权限校验、AI 编排
   ↓
repositories/     查询组装：分页、范围、上下文
   ↓
models/           SQLAlchemy ORM
   ↓
PostgreSQL
```

横切能力放在 `core/`：

- `permissions.py`：数据范围（Scope）计算
- `responses.py` / `errors.py`：统一响应与错误码
- `idempotency.py` / `confirmation.py`：幂等与确认令牌
- `security.py`：JWT、密码哈希
- `scheduler.py`：定时任务
- `storage.py`：文件上传下载安全

AI 集成只有唯一出口 `integrations/dify/`，密钥只存在后端 `.env`。

### 2.3 前端结构

前端不是多页面路由，而是「单壳三态」：

```
App.vue
├─ 访客态（非 /app、非 /login）  → VisitorPages.vue
├─ 登录态（/login）              → 登录页 + 视频背景
└─ 工作台态（/app/*）            → WorkspaceHeader + 侧边菜单 + 业务页面
```

业务页面由 `BusinessWorkspace.vue` 按 `api/resources.ts` 的契约动态渲染；报告、日报、学生详情等复杂页面使用专用组件。

### 2.4 部署拓扑

```
浏览器
  │
  ├─ 前端 Vite Dev Server :5173
  │
  └─ 后端 FastAPI :8000
        │
        ├─ PostgreSQL（云端 8.138.150.132:5433 / yue_education）
        │
        └─ Dify（http://8.138.150.132/v1，6 个工作流）
```

## 四、多视角工作流（答辩重点）

平台同一套数据，因角色不同呈现完全不同的入口、数据范围和可执行动作。下面按「视角」逐一说明。

### 4.1 访客视角（未登录）

**入口**：`http://127.0.0.1:5173/#/`

**可见页面**

| 路由 | 内容 | 关键交互 |
|---|---|---|
| `/` | 首页：宣传片、校园图集、项目卡、服务流程、政策概览 | 滚动进度、锚点跳转 |
| `/projects` | 留学项目列表（真实已发布项目） | 进入项目详情 |
| `/project/{id}` | 项目详情：简介、培养路线、费用、政策、FAQ | 「咨询项目详情」展开留资表单 |
| `/policies`、`/policy/{id}` | 留学政策（德国/新加坡） | 官方链接、关联项目 |
| `/events` | 活动资讯（真实开放活动 + 剩余名额） | 核对并报名、凭 token 取消 |
| `/about` | 公司介绍、六步服务流程 | CTA 进入项目 |

**访客可执行的三个写操作**

1. **留资**：姓名、电话、性别、城市、学历必填 → `POST /api/v1/public/leads`
   - 手机号规范化 + 数据库咨询锁，防止并发重复建档
   - `request_key` 幂等，失败重试不会重复创建
   - 一人一档：同号再次咨询只追加「再次咨询」跟进，不改归属
2. **活动报名**：锁行复查名额 → `POST /api/v1/events/{id}/registrations`
   - 访客获得一次性取消 token
3. **AI 客服**：右下角悬浮窗 → `POST /api/v1/assistants/visitor/messages`
   - 意图：FAQ / 项目推荐 / 留资草稿 / 活动报名草稿 / 闲聊 / 超范围
   - AI 只生成「确认卡」，访客点击确认后才落库

**访客视角的演示价值**：体现「获客入口 → 线索」的完整闭环，且不需要登录。

### 4.7 AI 助手视角（横切所有角色）

平台有四个 AI 入口，全部遵循「AI 不落库」：

| 形态 | 入口 | 能做什么 | 边界 |
|---|---|---|---|
| 访客客服 | 访客站右下角 | FAQ、项目推荐、留资/报名草稿 | 只读已发布项目与开放活动 |
| 企业助手 | 员工工作台右下角 | 查客户/待办/日报/服务/工单/心理；写操作给提议 | 读操作已鉴权；写操作必须确认 |
| 学生助手 | 学生工作台右下角 | 查本人档案/成绩/日程/申请；提交申请草稿 | 不向工作流传登录令牌 |
| 报告助手 | 日报/报告页右侧 | 收集日报草稿、准备报告条件 | 只返回提议，一键带入报告中心 |

**AI 安全设计（答辩加分项）**

1. AI 调用放在数据库事务之外：先 `rollback` 释放连接，再调 Dify，返回后重新校验权限签名。
2. 写操作返回 `Proposal` + `confirmation_token`，前端确认后调真实业务接口。
3. Dify 不可用时统一降级 `ai_status = UNAVAILABLE`，保留确定性指标与表单。
4. 报告正文由 AI 生成，但指标、事实、口径全部由后端确定性计算，并写入不可变快照。

## 五、权限与数据范围设计

### 5.1 角色来源

| 身份 | 来源 |
|---|---|
| 学生 | `sys_user.user_type = STUDENT` |
| 新人 | `employee_role = NEWCOMER` |
| 顾问 | `employee_role = ADVISOR` |
| 高级顾问 | `employee_role = SENIOR_ADVISOR` |
| 管理员 | `employee_role = ADMIN` |
| 部门主管 | `sys_department.head_user_id = 自己` |
| 班主任 | `sys_class.head_teacher_id = 自己` |

### 5.2 数据范围（Scope）

`core/permissions.py` 把「本人」映射到不同字段：

| 业务 | 「本人」字段 |
|---|---|
| 客户 | `owner_user_id` |
| 学生 | `advisor_user_id` |
| 行政服务 | `dept_id` |
| 售后工单 | `assignee_user_id` |
| 日报 | `employee_user_id` |
| 教务/成绩/心理 | `student_profile_id` |

计算规则：

- 管理员 → 全表
- 主管 → 本部门
- 员工 → 本人字段
- 学生 → 本人档案
- 匹配不到 → `id = -1`（谁都不给）
- 越权 → 404，不返回 403

### 5.3 敏感数据双闸门

- 投诉正文：需要 `can_handle_feedback`
- 心理数据：需要 `psych_access_enabled`，**管理员也不自动获得**
- 心理预警处置：主管/管理员 + 心理授权 + `psych_guard` 兜底

## 六、六类智能报告

| 类型 | 名称 | 数据来源 | 关键指标 | 特殊权限 |
|---|---|---|---|---|
| CUSTOMER_OPERATION | 客户经营报告 | 客户 + 跟进 | 新增、意向、签约、流失、转化率、环比 | 顾问即可 |
| DAILY_DAY | 日报日汇总 | 已通过日报 | 有效日报数、各类工作量、应报基数、覆盖率 | 顾问即可 |
| DAILY_WEEK | 日报周汇总 | 已通过日报 | 同上（周区间） | 顾问即可 |
| PSYCH_WEEK | 心理周报 | 心理观测 + 预警 | 观测学生日、覆盖率、情绪分布、高风险 | 心理授权 |
| COMPLAINT_WEEK | 投诉周报 | 售后工单 + 日报 | 未关闭、超期、满意度、响应/解决时长 | 主管/管理员 + 售后授权 |
| MANAGER_WEEK | 部门主管周报 | 部门日报 + 线索 + 事件 | 新增、签约、覆盖率 + 管理占位 | 仅主管/管理员，可提交生效 |

**生成流程**

```
选择类型与日期
   → 后端确定性计算 metrics + facts（口径写在 formula 字段）
   → db.rollback() 释放事务
   → Dify 只生成 narrative（失败则降级，保留指标）
   → 校验权限签名未变化
   → 落不可变快照 m5_report_snapshot
   → 前端核对、编辑、保存草稿
   → 主管周报可「确认提交」，提交后不可改
   → 导出 Word / PDF
```

## 七、典型端到端场景（答辩串联话术）

### 场景 A：从访客到签约（获客主链路）

1. 访客首页浏览德国双元制项目
2. 右下角 AI 客服咨询「费用和申请条件」
3. AI 给出项目推荐与留资确认卡
4. 访客确认留资 → 线索进入公共池
5. 顾问登录 → 客户管理 → 公共池认领
6. 补充资料 → 发起研判 → 查看匹配结果
7. 签约转学生 → 生成学生账号与档案
8. 学生登录 → 查看档案与项目

### 场景 B：学生服务闭环

1. 学生提交请假申请
2. 班主任/教务审批通过
3. 学生收到通知
4. 学生提交售后建议

6. 学生确认解决并评分 5 分
7. 投诉周报统计满意度与响应时长

## 八、答辩可突出的 8 个技术亮点

1. **AI 不落库**：所有 AI 输出都是草稿/提议，写库必须本人确认。
2. **事务外调 AI**：释放数据库连接再调模型，返回后重新校验权限签名。
3. **SQL 级数据范围**：权限不是前端隐藏按钮，而是数据库查询条件。
4. **越权 404**：不暴露数据存在性。
5. **一人一档 + 三渠道统一获客**：手机号加锁、幂等键、部门路由。
6. **五表原子转化**：签约转学生一个事务完成账号、档案、项目、状态、通知。
7. **报告口径可追溯**：每个指标带 formula，快照冻结生成条件与授权。
8. **敏感数据双闸门**：投诉与心理各自独立授权，管理员不自动获得。
