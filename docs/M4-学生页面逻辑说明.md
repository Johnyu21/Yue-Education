# M4 学生页面逻辑说明（给 M5 整合）

> 状态：M4 后端已实现。本文描述学生端页面逻辑与接口映射，供 M5 统一布局集成。
> 所有接口统一前缀 `/api/v1`，需 `Authorization: Bearer <token>`，响应为 `{code,message,data,request_id}`。

## 一、命名与通用约定

- 请求字段：snake_case（如 `service_type`、`request_key`）。
- 响应字段：camelCase（如 `studentProfileId`、`assigneeDisplayName`、`createTime`）。
- ID 一律字符串；时间 ISO 8601 带时区；纯日期 `YYYY-MM-DD`。
- 分页返回 `{items, page, pageSize, total}`，`page` 从 1 起，`pageSize` 默认 20 最大 100。
- 枚举全英文，前端查 `types/enums.ts` 翻译成中文。

## 二、页面与接口映射

## 三、助手浮窗交互（API030 关键）

请求：

```json
{"message_id":"uuid","conversation_id":"可选","message":"...","input_kind":"CHAT|CHECK_IN","context":{"page":"可选","selected_id":null}}
```

响应 `AssistantResult`：

```json
{
  "conversationId": "...", "messageId": "...", "answer": "给用户看的话",
  "sources": [], "missingFields": [], "proposal": null, "aiStatus": "LIVE", "warnings": []
}
```

**写操作提议确认流程（关键）**：
1. 助手返回 `proposal`（`operation=SUBMIT_SERVICE/SUBMIT_FEEDBACK/UPGRADE_INTEREST`），含 `preview`、`requestKey`、`confirmationToken`、`expiresAt`（5 分钟）。
2. 前端展示**完整卡片**让用户核对，用户点"确认"后调用对应普通业务接口（如 POST `/services`），**原样回传 preview 字段 + requestKey + confirmationToken**。
3. 后端校验令牌后真正落单，返回成功编号。**助手文本"已提交"不是业务回执**，以普通接口返回为准。

## 四、安全边界（前端不可依赖"隐藏按钮"）

- 学生只能看本人数据；工单响应**没有 `priority`**；助手响应**不含情绪/风险字段**。
- 心理观测结果、投诉正文、处理历史不返回学生端。
- 越权接口后端返回 404（不是 403），前端统一按"资源不存在"处理。
