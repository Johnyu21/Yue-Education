# 一键运行与首次拉取说明

## 在 Windows 上首次使用

1. 安装 Python 3.12（也支持 3.13）和 Node.js 22 / 24。Python 安装时勾选 Add Python to PATH，Node.js 保留 npm。安装后重新打开启动脚本。
2. 完整拉取本仓库，在项目根目录双击 **一键启动.cmd**。无须复制其他人的虚拟环境，也无须手动激活 Python。
3. 脚本会创建本机 backend/.venv、按 requirements.lock.txt 安装后端依赖，并用 npm ci 安装前端依赖。首次安装需要联网，可能等待几分钟。后续依赖未变化时直接复用。
4. 缺少 backend/.env 时，会从 backend/.env.example 自动生成，并为本机生成随机 JWT_SECRET。模板已指向小组云端业务库，首次启动只需按 CMD 提示输入 PostgreSQL 密码（不回显），脚本保存到本机 `.env`，以后不用重复输入。这是数据库密码，不是 Dify 网站登录密码。也可手动编辑以下配置：

~~~dotenv
POSTGRES_HOST=8.138.150.132
POSTGRES_PORT=5433
POSTGRES_DB=yue_education
POSTGRES_USER=postgres
POSTGRES_PASSWORD=向小组负责人获取数据库密码后填入
POSTGRES_SCHEMA=public
~~~

已有配置不会被覆盖。JWT_SECRET 会自动生成，通常无需修改。Dify 默认关闭，常规表单和业务操作可以先运行；AI 配置见 [Dify配置与正式项目测试账号使用说明](Dify配置与正式项目测试账号使用说明.md)。真实密码、KEY 只填本机 .env，不要写进模板或上传 Git。

服务器资料中的 `dify` 是 Dify 应用自己的数据库，不能填作本项目业务库。云端业务库 `yue_education` 已经存在，`postgres` 文档账号已通过只读连接验证，无需重复建库、迁移或初始化。
如果以前启动失败后留下了 `localhost/127.0.0.1:5432 + education + education账号 + 密码占位符` 的旧模板，新脚本会只更新这组尚未使用的默认连接；已有真实密码或进程环境覆盖时不会自动改连接。
如 CMD 仍提示“请填写 POSTGRES_PASSWORD”，确认已重新拉取最新 `tools/setup_project.py`，并通过双击入口打开可交互窗口；非交互运行需预先配置 `.env` 或环境变量。

5. 如果连接的是小组**已经完成迁移的业务数据库**，无需再次建库、迁移或初始化账号。再次双击 **一键启动.cmd**，等待“项目已就绪”，默认浏览器会自动打开首页。
6. 用完双击 **一键停止.cmd**。只停止本目录启动的进程，不停止其他软件或数据库。

也可以先双击 **一键准备环境.cmd**，只安装依赖并检查配置，不启动服务。如果尚未填数据库配置，程序会保留提示；填好后再运行即可。

## 日常地址

- 首页：http://127.0.0.1:5173/#/
- 登录：http://127.0.0.1:5173/#/login
- 后端接口文档：http://127.0.0.1:8000/docs

启动窗口可以关闭，服务继续运行。再次启动会检查服务并复用本目录的运行实例。修改 .env 后先停止，再启动，配置才会重新加载。脚本从自身位置定位项目，不依赖磁盘盘符、Windows 用户名或原项目路径。

## 使用全新数据库时

项目需要 PostgreSQL 15 及以上。数据库需要预先存在，账号需要有该库业务 schema 的建表和读写权限。日常启动**不会自动建库、迁移、清表、导入演示数据或重置账号密码**。

仅当你已确认使用的是自己新建的空数据库，并在 backend/.env 填好连接后，在项目根目录的 CMD 执行：

~~~bat
cd backend
.venv\Scripts\python.exe -m app.db.migrate
.venv\Scripts\python.exe -m scripts.bootstrap_admin --username admin --password-file bootstrap.credentials.txt
~~~

首个管理员的随机密码仅写入 backend/bootstrap.credentials.txt，不会显示在命令行；首次登录需修改。已有管理员的数据库不要重复初始化。云端已有业务库或旧版十九表库的操作见 [后端交付与运行手册](后端交付与运行手册.md)，不要盲目混用 deploy/schema.sql 和版本迁移。

演示账号属于数据库内容，Git 拉取代码不会复制数据库中的账号。连接同一个小组业务库才可直接使用该库已有账号；空库需先创建管理员。演示资料脚本及已有账号说明见 [Dify配置与正式项目测试账号使用说明](Dify配置与正式项目测试账号使用说明.md)。

## 遇到错误

| 提示 | 处理方式 |
| --- | --- |
| 未找到 Python | 安装 3.12 / 3.13 并勾选 PATH；重新打开脚本。自定义安装位置可用环境变量 YUE_PYTHON 指向 python.exe。 |
| 未找到 Node.js/npm | 安装 Node.js 并重新打开脚本。 |
| 缺少仓库文件 | 重新拉取完整仓库，保留根目录、tools、backend、frontend 的相对位置。 |
| pip / npm 安装失败 | 检查网络、公司代理和依赖镜像；按窗口原始错误处理，再次运行会重试。脚本不会偷偷修改依赖版本或绕过锁文件。 |
| backend/.venv 无法使用 | 常见于手工复制虚拟环境或移动目录。停止服务，将 .venv 移到项目外备份，再启动重新创建；不要删除业务文件。 |
| 请填写 POSTGRES_PASSWORD | 本机 `.env` 缺少密码；首次交互启动会不回显输入并保存，或手工填写后重试。Git 拉取不会获得其他人的密码。 |
| POSTGRES_DB 不能使用 Dify/系统库 | 使用 `yue_education`，不要照抄服务器资料中的 `dify`。 |
| 后端或数据库未就绪 | 检查 .env、数据库网络、防火墙和迁移状态；查看后端日志。 |
| 5173 / 8000 被占用 | 先使用对应旧目录的一键停止脚本结束旧实例，再启动当前项目；不会自动结束不属于本项目的进程。 |
| 另一个窗口正在准备环境 | 等待另一个窗口完成后再试，不要同时重复安装。 |

CMD 中可执行以下命令：

~~~bat
REM 只检查文件、依赖、配置，不安装或连接数据库
call tools\project_entry.cmd check
REM 重新安装依赖（先停止服务）
call 一键准备环境.cmd --repair
REM 不自动打开浏览器
call 一键启动.cmd --no-browser
~~~

## 随 Git 一起提交的内容

需要提交三个根目录 .cmd 文件、整个 tools 目录中的源码与测试、frontend/package.json 和 package-lock.json、backend/requirements.lock.txt、backend/.env.example，以及本说明。运行时产生的 .venv、node_modules、.env、logs、storage 保持忽略。这些内容由每位组员本机准备，不应通过复制上传解决。

首次启动的核心逻辑在 tools/setup_project.py；服务管理在 tools/local_project_runner.py 和 tools/frontend_dev_runner.cjs；公共 CMD 入口在 tools/project_entry.cmd。脚本读取自身目录，不保存其他人的绝对路径。

## 验证启动工具

在项目根目录运行，无需数据库：

~~~bat
backend\.venv\Scripts\python.exe -m unittest discover -s tools/tests -v
~~~

覆盖首次拉取、自动生成配置且不覆盖旧配置、缺少仓库文件、依赖失败可重试、锁文件更新触发安装、重复运行复用依赖，以及损坏虚拟环境保护。业务数据库连通性和迁移完整性在启动时通过 /api/v1/health/ready 单独验证。
