# 后端交付与运行手册

交付日期：2026-10-17。后端入口统一为 app.main:app；前端架构未调整。完整字段以同目录 openapi.json 和运行中的 /docs 为准。

## 已确认业务口径

- 员工日报由主管审核，通过版本进入汇总；重审期间仍采用上一通过版本。每次通过保存审核人、时间和内容历史。
- 日报只记录普通工作。心理、投诉的原文和明细留在专项模块。日报拒绝 PSYCH、COMPLAINT 工作条目及专项 source_event_id。自由文本需要员工按普通工作口径填写；系统不能以类别检查替代对自然语言的人工核对。
- 管理员可看全域普通经营数据，允许管理员没有部门。心理和投诉仍分别要求专项权限；撤回心理同意后不再提供相应观测、告警和历史敏感报告读取。
- 签约、入学、实收收入不混用。客户报告明确使用 signed_at 计算签约；当前意向、当前转化率不能冒充过去某日状态。没有收款来源，不计算实收收入。
- Dify 未就绪时默认禁用；确定性规则、业务表单、审核、提醒和报告事实统计可以独立工作。供应商实时连接另行验收。

## 数据库与本机配置

已单独建立云端 yue_education 与 yue_education_test，分别使用受限的 yue_app 和 yue_test 登录角色；不使用超级用户运行应用。测试库名由本轮确定。Dify 演示库没有作为教育业务库，也没有在其业务表上执行迁移或测试。

实际云端服务为 PostgreSQL 15.19；本轮 SQL 和真实数据库测试在这个版本执行。项目无需假定服务器已经升级到16。

连接配置在 backend/.env，测试配置在 backend/.env.test，均被 Git 忽略；不会把密码写到接口文档、镜像、命令参数或交付报告。配置模板在 backend/.env.example 和 backend/.env.test.example。服务和脚本不会读取桌面配置文件里的任意命令。

生产需设置 ENVIRONMENT=prod、DEBUG=false、随机 JWT_SECRET 和强数据库密码；禁止模拟 AI 模式。反向代理部署时，仅在 TRUSTED_PROXY_IPS 中登记实际可信的直接代理，代理需覆盖客户端自带的转发头；默认不信任任何 X-Forwarded-For。

## 本机启动

在 backend 目录执行以下 PowerShell 命令。已有 .venv 可以直接使用；新环境使用 Python3.12。

~~~powershell
python -m venv .venv
./.venv/Scripts/python.exe -m pip install -r requirements.lock.txt
./.venv/Scripts/python.exe -m app.db.migrate
./.venv/Scripts/python.exe -m scripts.bootstrap_admin --username admin --password-file bootstrap.credentials.txt
./.venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
~~~

管理员初始化只适用于尚无管理员的新库，密码只写入指定的新建本地文件；该文件被忽略，不在聊天或日志回显。首次登录后必须改密。首次环境不运行 seed.py 或 seed_m2.py，避免将演示数据混入正式业务。

GET /api/v1/health/live 检查进程；GET /api/v1/health/ready 检查数据库及全部迁移的版本和校验和。迁移未完成时返回503，不会伪报就绪。

## 容器与云端数据库

提供 backend/Dockerfile 和 deploy/docker-compose.backend.yml，镜像以普通用户运行，私有文件使用持久卷，端口默认仅绑定服务器回环地址。通过服务器反向代理配置域名与HTTPS。

~~~powershell
docker compose -f deploy/docker-compose.backend.yml build
docker compose -f deploy/docker-compose.backend.yml run --rm backend python -m app.db.migrate
docker compose -f deploy/docker-compose.backend.yml up -d
docker compose -f deploy/docker-compose.backend.yml logs --tail 100 backend
~~~

deploy/docker-compose.full.yml 是独立开发环境的数据库、一次性迁移任务及后端编排。其数据库不挂载旧 schema.sql，全部结构由版本迁移创建。提供 deploy/.env 的 POSTGRES_PASSWORD，并让 backend/.env 使用与之相同的口令。原有数据库 Compose 文件保留兼容，不应再混用其初始化SQL和新迁移初始化同一个库。

验证边界：本机 Docker Linux 引擎未运行，容器 build/up 尚未完成实跑；请勿将“文件已生成/配置可读”视为容器部署验收通过。原生 Python 运行和云端数据库测试单独记录。

## 测试与隔离

~~~powershell
cd backend
./.venv/Scripts/python.exe -m scripts.test_backend -q --tb=short
~~~

测试入口仅读取 .env.test，要求 ENVIRONMENT=test、TEST_DATABASE_ENABLED=true、库名以 _test 结尾；每轮创建随机 test_ schema，迁移、测试后删除本轮 schema。直接 pytest 不符合护栏时会失败，不能把 .env 改为正式库后运行测试。所有测试资料均为合成夹具。

支持指定单个文件，例如 scripts.test_backend -q tests/test_integration_reports.py。阶段日志在 backend/logs；该目录被忽略。开发依赖与文档导出能力已经统一，requirements.lock.txt 是当前验证环境的精确版本集合，requirements-m2.txt 和 requirements-m5.txt 仅保留安装兼容入口。

## 迁移与旧数据

迁移文件位于 backend/migrations，按001到008顺序执行并保存 SHA256 校验和，同一个迁移被改动会拒绝继续。应用启动不隐式建表、清表或自动改结构，发布时显式执行迁移。

已有未纳管的十九表库需先备份，然后运行 scripts.adopt_baseline。该工具在临时 schema 中建立参考结构，比较字段、类型、非空、身份列、默认值、约束和索引；不一致就拒绝纳管，不猜测旧库结构。已有完整M5三表可同时识别。纳管后再运行 app.db.migrate。

~~~powershell
./.venv/Scripts/python.exe -m scripts.adopt_baseline
./.venv/Scripts/python.exe -m app.db.migrate
~~~

008将旧 employee_daily_report 保留并建立 legacy_daily_mapping，原文及源JSON保留。历史 SUBMITTED 仍要实际审核；不会自动变为通过。出现同员工同日期的新旧日报冲突时整笔迁移中止，需先核对数据。此前未分级的M5历史自由文本保守保留专项访问限制，新普通日报按本次确认口径运行。

已有非法日期字符串会使005整体失败，需先人工核对修正。业务新增数据后不执行反向DROP；代码回退需保留新表，必要时使用已验证备份恢复到独立恢复库。

## 备份与恢复

服务器需安装与PG15兼容的 pg_dump/pg_restore。备份期间暂停写入，使数据库和私有文件来自同一时点。执行前确认输出目录位于私有文件目录之外。

~~~powershell
./.venv/Scripts/python.exe -m scripts.backup --output ../backups/2026-10-17
./.venv/Scripts/python.exe -m scripts.restore --source ../backups/2026-10-17 --target-database yue_education_recovery --files-output ../recovered-files
~~~

数据库管理员需预先建立空的 *_recovery 数据库，并给恢复账号必要权限；恢复工具拒绝原业务库及非空目标。工具校验备份哈希、恢复迁移版本，使用单事务pg_restore和安全tar路径过滤。恢复后应启动隔离后端，检查登录、日报审核、报告导出及私有文件下载；核对后再安排切换，不直接覆盖正式库。

本机未安装 pg_dump/pg_restore，完整备份恢复演练尚未实跑。脚本和运行步骤已经提供，这项仍是部署前必验项。云端教育业务库初始化前已确认没有任何业务表，因此本次初始化没有旧业务数据迁移风险。

## 定时任务与运行维护

SCHEDULER_ENABLED=true 才启用扫描。任务用事务级 PostgreSQL advisory lock，未发送事件过滤、稳定排序及 SKIP LOCKED 批处理；超过200条会由后续轮次继续扫描。重设提醒使用实际 reminder_revision，通知在同一业务事务内幂等写入。服务停止会通知调度线程退出。

短期访客草稿、员工候选与限流均使用 PostgreSQL 共享状态，多进程不会各自持有独立桶。过期状态在访问/写入时清理；员工候选绑定登录主体，实际取详情再次鉴权。访客 conversation_id 是不透明的短期访问句柄，不能记录到公开日志或分享给他人。

日志不输出SQL参数、密码、完整投诉或心理原文；未预期错误通过 request_id 与异常类型定位。私有文件不作为静态目录发布；下载接口重新验证当前身份和资源关系。生产查询默认排除TEST成绩/日程，心理报告排除演示学生。
