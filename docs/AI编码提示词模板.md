# AI 编码提示词模板

> 状态：**可用**　产出日期：2026-10-16　负责人：P1（M1）
> 读者：**全员**（M2 / M3 / M4 / M5）
> 用途：给全班用 AI 写代码时，**统一贴这段**，避免各写各的

---

## 一、为什么需要这个

**问题**：如果只跟 AI 说"帮我写一个线索接口"，它会**自己编**——
自己定返回格式、自己决定怎么连库、自己决定错误怎么抛。

**结果**：五个人用 AI 写出来的代码，**风格完全不同**，合并时对不上。

**所以**：**每次让 AI 写代码，先把"公共约定"喂给它**。这样它照约定写，
你只需要说"做什么"，它**自动遵守全组的规矩**。

> **这份模板就是那段"公共约定"** —— 每次复制粘贴，改最后一行任务即可。

---

## 二、怎么用（三步）

1. **复制**下面第三节的模板
2. **替换** `【任务】` 那部分，填你要做的功能
3. **粘贴**给 AI（Cursor / Claude / 其他），让它写

**如果任务涉及某模块的特有内容**（如心理、报告），
再**从第四节补一段**贴进去。

---

## 三、通用提示词模板（直接复制）

```text
你在为"粤教留学服务平台"写后端代码。严格遵守以下约定，不要自行发挥。

## 技术栈
Python 3.12 + FastAPI + SQLAlchemy 2.0 + PostgreSQL 16。现有代码在 backend/app/。

## 必须遵守的公共约定

1. 返回格式：一律用 `app.core.responses.ok(data)` 包装返回值。
   不要自己 `return {...}`，不要自己拼 code/message。

2. 报错：抛 `app.core.errors` 里现成的异常类
   （NotFoundError / StateConflictError / ForbiddenError 等）。
   不要自己 try/except 吞异常，不要自己构造错误响应。

3. 数据库：用 `db: Session = Depends(get_db)` 注入。
   不要自己建连接，不要自己 commit（事务由 service 层管）。

4. 鉴权：需要登录的接口加 `user: SysUser = Depends(require_password_changed)`；
   只是"要登录"的加 `Depends(get_actor)`。

5. 枚举值：数据库和接口**一律用英文大写**（NEW / ADVISOR / PENDING），
   中文只在前端展示。取值表见 `M1-01-公共契约冻结.md`。

6. ID：接口返回的 id **转成字符串**（防 JS 精度丢失）。

7. 时间：数据库存 UTC，接口输出 ISO 8601（如 "2026-10-15T02:10:00Z"）。

8. 分层：controllers（路由）/ services（业务+事务）/ models（表）/ schemas（输入输出）。
   model 对数据库，schema 对接口，不要混。

## 明确禁止
- 不要新增表（表结构已冻结在 schema.sql，19 张）
- 不要自己造返回格式或错误码
- 不要吞异常（except: pass）
- 不要泄露 SQL、密码、堆栈到响应里
- 不要绕过数据范围直接查全表（越权风险）
- 不要引入新框架（Redis / MQ 等）
- 不要写死配置（从 app.core.config.settings 读）

## 参考资料
- 公共契约：M1-01-公共契约冻结.md
- 表结构：M1-02-建库验证.md、schema.sql
- 响应/异常用法：M1-03-统一响应与Session.md
- 认证用法：M1-04-认证.md

## 【任务】
（这里填你要做的具体功能，例如：）
实现 API016 客户研判：POST /api/v1/crm/leads/{id}/assessments
- 权限：负责该线索的顾问、本部门主管、管理员
- 输入：简历文本或文件
- 逻辑：调用 Dify WF_PROFILE 提取画像，按规则判硬条件，保存最近一份报告
- 输出：画像卡（匹配度、命中项、缺失项、建议）
- 要写测试
```

## 四、各模块补充（按需追加）

**任务涉及以下内容时，把对应一段加到模板末尾**：

### M2（客服 / 研判 / 活动）
```text
## 本模块补充
- Dify 调用走 app/integrations/dify.py 适配器，不要直接在 controller 里发 HTTP
- Dify 返回要校验 schema；不符合约定抛 AIBadResponseError
- 活动报名要"锁行 + 查容量 + 写记录"在同一事务，防超卖
```

### M3（企业助手 / CRM）
```text
## 本模块补充
- 线索归属改动用 version 乐观锁（WHERE id=? AND version=?），影响行数为 0 抛 VersionConflictError
- 转学生是一个事务：建账号 + 建档案 + 建课程关联 + 改线索状态 + 写跟进，任一步失败全部回滚
- 状态变更必须同时写时间字段（如 SIGNED 必须带 signed_at），否则数据库会拒
```

### M4（学生助手）
```text
## 本模块补充
- 学生只能看自己的数据；员工按数据范围（本人/本部门），范围外一律 NotFoundError（不是 Forbidden）
- 请假审批：状态更新与通知写库在同一事务
- 成绩表本轮只读（data_source='TEST'），不提供增删改接口
```

### 心理相关（敏感）
```text
## 心理模块补充（⚠️ 最敏感）
- 权限双重校验：角色 + psych_access_enabled 标志
- 心理数据不进通知正文、不进日志
- 预警必须人工确认，不能自动置为已处理
```

### M5（报告 / 前端）
```text
## 本模块补充
- 报告实时生成，不新建报告表
- 统计口径由后端算好（metrics），AI 只负责组织文字
- 前端枚举展示要映射成中文（见 M1-01 对照表）
```

## 五、注意事项

| ❌ 不要 | 为什么 | ✅ 应该 |
|---|---|---|
| 只说"写个XX接口" | AI 会自己编约定，风格跑偏 | 先贴公共约定，再给任务 |
| 让 AI 一次写整个模块 | 出错范围大，难排查 | 一次一个任务（对应任务卡） |
| 不提供表结构就让它写 | AI 会编字段名 | 把 `schema.sql` 相关表给它 |
| 让 AI 自己决定返回格式 | 破坏全组一致性 | 模板里已经写死了 |
| 直接信 AI 说"做好了" | 它可能没测 | **让它给出测试命令 + 实际输出** |
| 让 AI 改公共文件 | 会影响全组 | 公共文件（M1 的）变更要先说 |

### ⚠️ 两条硬规矩

1. **AI 写完必须自己跑一遍测试** —— 别直接信"已完成"。
   让它给你**命令 + 实际输出**，你亲眼看到才算。

2. **公共文件（`app/core/`、`schema.sql`）不要自己改** ——
   那是 M1 的，改了会影响全部人。要改先跟 P1 说。
