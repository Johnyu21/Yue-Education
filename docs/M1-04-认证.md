## 一、验收结果

**验收标准**：旧 token 改密后失效，临时会话仅能改密。

```
$ pytest tests/ -q
19 passed
```

### ⭐ 核心验收点：改密后旧令牌立即失效

**实测过程**：
```
① 登录 advisor01 → 拿到旧令牌
② 用旧令牌访问 /me          → 200 ✅（此时有效）
③ 改密（旧密码→新密码）      → 成功
④ 用【旧令牌】访问 /me       → 401 TOKEN_EXPIRED ✅（立即失效）
⑤ 用【新密码】登录           → 成功 ✅
⑥ 用【旧密码】登录           → 失败 ✅
```

**原理**：改密时 `token_version` +1。令牌里存着旧版本号，
`get_actor` 发现"令牌版本 ≠ 数据库版本" → 拒绝。
**所以改密 = 所有旧设备自动登出。**

## 二、大家怎么用（重点）

### 2.1 让接口需要登录

```python
from app.core.deps import get_actor, require_password_changed
from app.models.user import SysUser

# 只要登录就行
@router.get("/leads")
def list_leads(user: SysUser = Depends(get_actor)):
    ...

# 要求已改过初始密码（首次登录的学生必须先改密）
@router.get("/my/progress")
def my_progress(user: SysUser = Depends(require_password_changed)):
    ...
```

**两个依赖的区别**：

| 依赖 | 含义 | 用在哪 |
|---|---|---|
| `get_actor` | 只要登录 | 改密接口本身、`/me` |
| `require_password_changed` | **登录 + 已改初始密码** | **绝大多数业务接口** |

### 2.2 判断当前用户身份

```python
user.user_type          # "STUDENT" / "EMPLOYEE"
user.employee_role      # "NEWCOMER" / "ADVISOR" / "SENIOR_ADVISOR" / "ADMIN"
user.dept_id            # 部门 id（数据范围用，见 M1-05）
user.is_student         # True/False
user.is_employee        # True/False
user.can_handle_feedback      # 是否有售后权限
user.psych_access_enabled     # 是否有心理数据权限
```

## 三、⚠️ 三条安全设计（别破坏）

| # | 规则 | 为什么 |
|---|---|---|
| 1 | **密码只存 bcrypt 哈希** | 数据库被看到也读不出原密码 |
| 2 | **登录失败提示统一**"用户名或密码错误" | 不透露"用户名是否存在" |
| 3 | **令牌版本比对**（`token_version`） | 改密/禁用后旧设备立即失效 |

**另外两条**：
- **JWT 算法固定在服务端**（`HS256`），**不接受客户端指定**——防"算法混淆攻击"
- **临时密码用随机源生成**，**绝不用手机号后 6 位**这类可推导方式

## 四、初始化账号（M1 部署时做）

**管理员账号不能写死在 git 里**（会泄露），用一次性初始化：

```bash
cd backend && source .venv/bin/activate
python - <<'PY'
from app.core.security import hash_password
print(hash_password("你的密码"))
PY
# 把输出的哈希贴进 SQL 插入 sys_user
```

**签约转学生时**（M3 的 `convert` 事务里）：
```python
from app.services.auth_service import reset_student_password
plain = reset_student_password(db, new_student)   # 返回明文，只展示一次
# → 线下交付给学生，首次登录强制改密
```
