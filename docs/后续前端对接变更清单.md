# 后续前端对接变更清单

本轮仅交付后端，未修改 frontend 架构。详细请求schema见 openapi.json；所有业务ID输出为字符串，整数ID和UUID不能混用。响应统一 code/message/data/request_id，校验失败422，范围外对象404，能力不足403，版本或状态冲突409，未配置外部AI通常503。

## 通用写入规则

- 对schema包含request_key的业务操作，每次新的操作生成新的request_key UUID，网络重试使用相同键和相同内容。相同键改内容会409。
- 对schema包含expected_version的更新请求传入该版本；申请进度使用expected_sequence。组织管理沿用原字段结构，事务内由ORM版本检测并发写入。不要在409后静默改版本重放，先刷新并让用户核对。
- 所有时间值和时间查询参数须带Z或+08:00；自然日使用YYYY-MM-DD。金额与成绩数值不要使用浮点推断业务结论。
- AI写提议仅返回 proposal，不会执行操作。展示 preview，用户点击确认后，将 requestKey、confirmationToken、expectedVersion 和原预览内容交给对应普通业务接口。修改预览需要重新生成确认卡，或走明确的手工表单提交。
- 用户主动提交普通表单保留原有 confirmed 默认语义，但显式false会被拒绝。访客留资/报名默认未确认，必须提交confirmed=true。切勿让AI代替用户确认。

企业助手的跟进卡新增 nextFollowUpAtProvided：false表示提交时省略next_follow_up_at并保留现有计划；true且nextFollowUpAt=null表示明确清空。显示字段的camelCase与业务提交的snake_case需按操作映射，不应把展示卡原样作为所有接口的请求体。

## 登录与文件

GET /api/v1/auth/me 新增 version、isAdmin、isDeptHead、headOfDepartmentIds、classTeacherOfIds、canHandleFeedback、psychAccessEnabled，组织关系实时来自数据库。首次改密、停用、变权后旧令牌失效。

通讯录仅返回有效员工，学生使用本人档案中的顾问和班级联系信息。公开活动查询拒绝DRAFT等管理状态。

POST /api/v1/files 上传仍返回object_key；新GET /api/v1/files/{object_key}是鉴权私有下载。上传MIME、扩展名和内容必须相符，大小上限10MB。旧doc/xls可以存储，但简历自动抽取支持PDF、DOCX、XLSX、UTF-8文本；不能解析时明确422。

POST /api/v1/transcriptions 使用 multipart 的file，不再接收空JSON占位。未配置供应商返回功能不可用；成功text须让用户核对，requiresConfirmation=true。

| PUT | /api/v1/employees/students/{student_id}/scores/{score_id} | 员工修订，传expected_version |

## 日报

日报正式事实源是m5_daily，API082–087兼容路径保持，UUID作为不透明字符串。M5前缀的完整路径同时提供。原employee_daily_report不再写入。

- PUT /api/v1/m5/dailies：report_date、content、original_text、request_key，修订传expected_version。
- GET /api/v1/m5/dailies：offset/limit分页，默认50，上限200，返回数组；兼容 /api/v1/me/daily-reports 同口径。
- POST /api/v1/m5/dailies/{id}/action：action为SUBMIT/WITHDRAW/APPROVE/RETURN，expected_version、request_key，退回需reason。
- GET /api/v1/m5/dailies/{id}/history：通过版本历史，重新鉴权。
- API083兼容PUT /api/v1/me/daily-reports/{report_date}。
- API084–087的submit/withdraw/approve/return路径仍可用，请见OpenAPI。

状态DRAFT→SUBMITTED→APPROVED或RETURNED；RETURNED可以重提，SUBMITTED可撤回。主管无需填写日报，不能自审。审核通知与DAILY_REPORT_REVIEW/DAILY_REPORT_RETURN待办已接入统一工作台。

content包含work_summary、items、difficulties、next_plan；next_plan可空，没有困难填“无”。日报只记录普通工作，PSYCH/COMPLAINT条目和专项事件引用会422，敏感细节在专项模块维护。员工有专项权限不影响其普通日报由普通主管审核。

已通过日报修订后变DRAFT，汇总继续使用旧的approved_version，直至新版本实际通过。历史源不全的数据不会补造审核证据。

## 报告预览、保存与导出

支持CUSTOMER_OPERATION、DAILY_DAY、DAILY_WEEK、PSYCH_WEEK、COMPLAINT_WEEK，额外保留MANAGER_WEEK。

1. POST /api/v1/reports/preview（或 /api/v1/m5/reports/preview），提交type/start_date/end_date/employee_user_ids。
2. 展示返回的metrics、facts、warnings、ai_status、narrative及snapshot_id；UNAVAILABLE表示没有生成AI文案，但指标和事实仍可用。
3. POST /api/v1/m5/reports 保存时必须提交本人的snapshot_id和相同筛选条件，另传title/narrative/request_key。不得自行拼接另一次预览的指标。
4. 修改已保存报告传id和expected_version，类型、日期、员工范围不可变；换条件需要重新预览另存。人工修改正文不会重新计算历史指标。
5. GET /api/v1/m5/reports/{id}/export/docx 或pdf。敏感权限、当前学生范围和心理同意在读取/导出时重新检查；失权后403/404。

列表最多返回最近200份报告。新接口不返回无限历史集合。ai_status为LIVE/MOCK/UNAVAILABLE，保存后沿用快照的来源状态；人工编辑正文属于用户行为，不代表重新执行AI。

## 助手

企业和学生助手保留各自入口；M5会话助手负责日报收集和报告生成条件准备。AI暂停时展示明确不可用状态并保留表单入口。学生JWT不再传给Dify；任何工作流都不自行POST业务写接口。

conversation_id只用于定位会话，不授予对象权限。员工候选缓存绑定登录用户；会话权限范围改变时清理历史草稿。用户不要将访客会话句柄作为公共链接分享。
